# SymPy corpora

The reference is SymPy 1.14.0. This directory holds the cases extracted from
SymPy by [`tools/sympy-reference`](../sympy-reference/README.md), the harness
that replays them against the symjs public API, and the converter that turns
them into vitest tests.

| Part | Files |
|---|---|
| Doctest corpus | `corpus.json` |
| Unit-test corpus | `tests-corpus/index.json` and category shards |
| Replay | `harness.ts` (shared), `tests-harness.ts` (unit tests), `ports.ts`, `ode-checks.ts` |
| Adapter routes | `adapter-inventory.json`, generated by `adapter-audit.ts` |
| Corpus tests | `totests/` generates `packages/symjs/tests/**/*.corpus.test.ts`; `corpus-report.ts` is the vitest reporter of `bun run corpus:report` (see [CONTRIBUTING.md](../../CONTRIBUTING.md)) |

## Harness replay

The replay compares each corpus with SymPy using its own denominator and gap
list. Only executed assertions count toward agreement. The generated tests
also contain expected failures and todos, so the replay checks cases those
tests cannot yet verify through the public API.

| Corpus | Replay | Ratchet | Report |
|---|---|---|---|
| Doctests | `compat/compat.test.ts` | `doctest-known-gaps.json` | [Doctest agreement and API presence](../../docs/doctest-compat-report.md) |
| Unit tests | `compat/tests-compat.test.ts` | `tests-known-gaps.json` | [Unit-test agreement](../../docs/unittest-compat-report.md) |

Run the harness from the repository root. Select a project to replay a single
unit-test category, or set `CAT` to list individual doctest outcomes in a category.

```sh
bunx vitest run --config tools/sympy-corpus/compat/vitest.config.ts
bunx vitest run --config tools/sympy-corpus/compat/vitest.config.ts --project unit-geometry
CAT=geometry bun run corpus:compat:category
```

With pnpm, use `pnpm exec` for `bunx` and `pnpm run` for `bun run`.

Unit-test replay runs one named Vitest project per category. It
reuses the doctest serializer format, deserializer and public API adapters.
Synchronous calls have a 30-second deadline for core/polys and 5 seconds for
other categories. Set `COMPAT_TESTS_TIMEOUT_MS` to a positive integer to override
the per-case deadline on slower machines; the generated report records it.
Timeouts are failures. Missing adapters and input conversion
failures cannot satisfy exception assertions; invoked exceptions with different
classes are accepted but counted separately. Reports distinguish wrong results,
missing APIs/adapters, unsupported values, conversion errors, API exceptions,
comparison errors, missing expected exceptions, and timeouts.

The doctest replay writes `compat/results/report.json`. A full unit-test replay
writes `compat/results/tests-report.json`, and each category writes its failures
to `compat/results/tests-results/<category>.jsonl`. Git ignores these files.
With `UPDATE_KNOWN_GAPS=1`, the doctest replay updates its gap list, and a
single coordinator updates the unit-test ratchet after all categories finish.
Partial unit-test runs leave the aggregate unit-test report and ratchet intact. Existing
unit-test IDs must remain stable when expanding coverage. Compare old cases
separately from newly measured failures, and verify the doctest corpus and its
ratchet remain unchanged. See [CONTRIBUTING.md](../../CONTRIBUTING.md) for the
required coverage, type, lint, build and size checks.

Replay deadlines remain in the measured totals and failure groups. The ratchet
stores their IDs in `timeouts` as inconclusive observations. A deadline cannot
establish a correctness regression, and a completed result cannot resolve a
previously unfinished assertion as a confirmed fix. Completed assertions still
use the strict existing regression/fixed-case checks.
