# Compatibility measurements

The reference is SymPy 1.14.0. The doctest and upstream unit-test corpora have
independent denominators and ratchets. Neither report measures unexecuted
assertions as successes.

| Measurement | Reference input | Replay | Ratchet | Report |
|---|---|---|---|---|
| Doctests | `corpus.json`, generated by `extract.py` | `compat.test.ts` and `harness.ts` | `known-gaps.json` | `REPORT.md`, `report.json` |
| Unit tests | `tests-corpus/index.json` and category shards, generated by `extract_tests.py` | `tests-compat.test.ts`, `tests-harness.ts`, shared `harness.ts` | `tests-known-gaps.json` | `TESTS-REPORT.md`, `tests-report.json` |

Run all compatibility checks with:

```sh
npx vitest run --config compat/vitest.config.ts
```

For unit-test extraction and selective replay:

```sh
pnpm compat:extract-tests --only geometry,vector
pnpm compat:extract-tests --only diffgeom
pnpm compat:test-extract
npx vitest run --config compat/vitest.config.ts --project unit-geometry
```

The unit-test extractor scans nested test directories in 31 base areas. Its
`FILE_SCOPE`, `EXCLUDED_AREAS` and `MIXED_DEFAULTS` tables define inclusion and
technical exclusions; the report lists every excluded file. Categories are
actual top-level packages: `integrals`, `series`, `concrete`, and `calculus`
are separate, and all function subpackages belong to `functions`.

`tests-corpus/index.json` lists each category's case shards, byte sizes,
omission counts, test statuses and extraction time. `<category>.audit.json`
contains source-level omission records and individual test statuses. Case
arrays have one JSON object per line and split at 25 MB, preserving record and
field order. `--only` replaces entire selected categories and retains all
others. A full extraction uses four independent processes; `--jobs` changes
that limit. Each upstream test has a 30-second deadline, and timed-out tests
lose all partial observations. `--baseline` migrates a legacy corpus by retaining
all previously observed modules and extracting only unmeasured modules.

Replay runs one named Vitest project/test per category, with four workers. It
reuses the doctest serializer format, deserializer and public API adapters.
Synchronous calls have a 30-second deadline for core/polys and 5 seconds for
other categories. Set `COMPAT_TESTS_TIMEOUT_MS` to a positive integer to override
the per-case deadline on slower machines; the generated report records it.
Timeouts are failures. Missing adapters and input conversion
failures cannot satisfy exception assertions; invoked exceptions with different
classes are accepted but counted separately. Reports distinguish wrong results,
missing APIs/adapters, unsupported values, conversion errors, API exceptions,
comparison errors, missing expected exceptions, and timeouts.

A full run generates the Markdown report, a compact JSON summary, and ignored
`tests-results/<category>.jsonl` failure details. With `UPDATE_KNOWN_GAPS=1`, a
single coordinator updates the unit-test ratchet after all categories finish.
Partial project runs leave the aggregate report and ratchet intact. Existing
unit-test IDs must remain stable when expanding coverage. Compare old cases
separately from newly measured failures, and verify the doctest corpus and its
ratchet remain unchanged. See [CONTRIBUTING.md](../CONTRIBUTING.md) for the
required coverage, type, lint, build and size checks.

Repeated omission records share a `count` in category audit files. Counts retain
every examined loop observation without repeating identical source metadata.
`pnpm compat:extract-tests --compact-audits` losslessly repacks these audits
without changing case records or re-executing upstream tests.

Replay deadlines remain in the measured totals and failure groups. The ratchet
stores their IDs in `timeouts` as inconclusive observations. A deadline cannot
establish a correctness regression, and a completed result cannot resolve a
previously unfinished assertion as a confirmed fix. Completed assertions still
use the strict existing regression/fixed-case checks.
